### 4.1 CI 后端测试跑两遍（E7）

- **现状**：`ci.yml` 先跑一遍全量 `pytest`，再用 `TEST_LEARNER_KNOWLEDGE=rule` 跑第二遍全量，检查换掉学习者知识模型（默认 `course` → `rule`）后系统照常工作。AGENTS.md 也把两遍都列为必跑。
- **代价**：后端这一项在 CI 上约 18 分钟，本地一遍约 12 分钟。
- **审查建议**：第二遍只跑学习者相关测试。
- **建议**：不缩小范围。大多数提问测试都经过更新学习者状态的流程，划不清哪些"与学习者相关"，缩小会漏问题，还要改规则。改为让两遍在 CI 里**并行**跑（两个 job 或 matrix）：覆盖不变，等待时间约减半。**待做**。

### 4.2 组件热切换偏重（A5）

- **现状**：管理员在页面改系统设置（本地模型、检查器、知识模型等）后不重启即生效。每个进程（api、worker）定期心跳并检查设置版本；版本变了就在后台重建一整套组件再一次性替换，进行中的请求继续用旧的；所有进程到新版本才算生效；切换中再改设置返回 423；出错或超时自动回滚。代码在 `platform/components.py` 和 `platform/settings.py`，约 700 行，是项目里最复杂的一块。
- **为什么偏重**：按"多进程、不停机"设计，而实际部署只有 1 个 api 和 1 个 worker，重启只要几秒。而且登录限流、网关信号量、web search 缓存都在进程内（审查 A6），api 本来就不能开多副本。
- **建议**：保持现状，不删也不扩展。已写好、有测试，设计文档（course-structure.md 6.5）要求设置不重启生效；删掉要改设计和测试，风险大于收益。不再给热切换加新功能；交接时说明这是最难维护的一块，并在 OPERATIONS.md 写明 api 只能单副本运行。
